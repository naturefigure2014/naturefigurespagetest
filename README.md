# NATURE FIGURE Astro

Astroで構築する「ネイチャーフィギュアのページ」の静的サイトです。

## 見出しの補足

フィギュアやタイトルのフロントマターに `titleEyebrow` を指定すると、
メーカーとシリーズ名の後に補足を表示します。`title` には本来の名前を指定します。

```yaml
titleEyebrow: "特別展『深海』会場特別先行販売"
title: "ダイオウイカ 精密ポリストーンフィギュア"
```

## タイトルのラインナップ

通常は `figureIds` にフィギュアのIDを列挙します。見出し別に表示する場合は、
同じIDを `lineupGroups` にも指定します。グループと各IDは記載順に表示され、
すべてのフィギュアを重複なくいずれかのグループに含める必要があります。
原型師ページでは、グループを指定しない場合も `figureIds` の記載順に表示されます。
グループを指定しない場合、見出しは通常「ラインナップ」です。
`lineupHeading` で変更でき、空文字にすると非表示になります。
原型師ページでは未指定の場合も非表示です。グループの `title` を省略または
空文字にした場合も、そのグループの見出しは表示されません。

```yaml
figureIds:
  - maker/series/001
  - maker/series/002
lineupGroups:
  - title: "北海道"
    figureIds:
      - maker/series/001
  - title: "東北"
    figureIds:
      - maker/series/002
```

旧HTML生成時に続きのページの順序を指定する場合は、対象フォルダで
`--continuation hokkaido.html --continuation tohoku.html` のように繰り返し指定します。
指定しない場合は従来どおり同じフォルダのHTMLを自動検出します。

## クリエイター一覧

各クリエイターの `href` からフィギュアのフォルダを特定し、
配下の個別フィギュアをカードで表示します。`figureIds` がある場合は
その記載順を優先し、未掲載のフィギュアは後に表示します。
一覧ページへのリンクを設定しない場合は `figureFolder` に
`sculptors/KiraKazuya` のようなフォルダIDを指定できます。

## 今回の変更（FIGURE画像）
- FIGURE詳細ページで、複数画像を含む話題は「画像2/3・説明1/3」のレイアウト。
- 話題内の画像をクリックすると拡大表示するライトボックスを表示。
- 拡大表示は元画像の縦横比を維持し、PC・スマートフォンの両方に対応。
- 背景クリック、閉じるボタン、Escキーで閉じられます。
- 既存の画像ファイル名をそのまま利用する方式は維持しています。

## FC2テストサイトへの公開

GitHub Pagesへの公開とは別に、GitHub ActionsからFC2の
`https://ninjaaquarium.web.fc2.com/test/` に公開します。
`main` へのpush後に自動でビルド・公開し、手動実行もできます。

1. FC2の管理画面「FTP設定」でFTP接続ロックを解除し、FTPホスト名、
   ユーザー名、FTPパスワードを確認します。FC2 IDのパスワードとは異なります。
2. FC2に `test` ディレクトリを作成します。FTPログイン直後のディレクトリから
   `./test/` が公開URLの `/test/` に対応することを確認してください。
   このディレクトリはデプロイ専用とし、事前に既存データをバックアップします。
3. GitHubリポジトリの **Settings → Secrets and variables → Actions** で、
   `FC2_FTP_SERVER`、`FC2_FTP_USERNAME`、`FC2_FTP_PASSWORD` を
   repository secretsとして登録します。パスワードをソースやログに書かないでください。
4. このワークフローを `main` に反映すると自動公開が始まります。以後も `main` に
   pushすると、自動でビルドして実際に転送します。FTP接続ロックが有効な場合は失敗します。
5. 手動実行する場合は **Actions → Deploy test site to FC2 → Run workflow** から、
   `Preview changes without uploading` を有効にして変更対象を確認できます。
   実際に転送するにはプレビューを無効にします。公開後は画像とリンクも確認してください。
6. ビルド成果物は `fc2-site-dist` というGitHub Actions artifactとして7日間保存します。
   デプロイが失敗した場合は同じ実行の **Re-run jobs → Re-run failed jobs** を選びます。
   成功したbuild jobは再実行されず、保存済み成果物をdeploy jobで再利用します。
   **Re-run all jobs** を選ぶとビルドからやり直します。ワークフローを修正して
   再実行する場合は、`artifact_run_id` に失敗した実行のIDを指定すると、
   その実行の成果物を使ってビルドを省略できます（成果物の保存期間は7日間です）。
   FC2向けビルドでは、日本語などASCII以外の出力パス要素をASCII名に変換し、
   生成されたHTML/CSS内のリンクも変換後の名前に合わせます。GitHub Pages向けのURLは変わりません。

デプロイではファイル内容のSHA-256を前回の正常転送結果と比較し、新規・変更分だけを
転送します。初回、転送途中で失敗した後、または `Transfer all files` を有効にした場合は
全ファイルを転送します。転送中の失敗を見逃さないため、状態ファイルを未完了にしてから
転送し、全転送成功後に更新します。プレビューでは状態を変更しません。
転送後は一時確認ファイルを `/test/` からFTPで取得して転送先を検証し、
確認ファイルを削除してから状態を完了にします。これは転送先の確認であり、
全ファイルの内容を個別に検証するものではありません。
失敗時には確認用の `fc2-deploy-probe-*.txt` がサーバーに残る場合があります。
旧バージョンの状態記録は転送先が誤っている可能性があるため、修正版の初回実行では
自動的に全件を `/test/` に再転送します。完了後は通常の差分転送に戻ります。
以前誤って作成された `/test/stage/` は自動削除しません。復旧後に内容を確認してから
必要に応じてFTPソフトで整理してください。
状態ファイルを直接取得し、FTPサーバーが明確に「ファイルが存在しない」と返した場合は
初回として全件転送します。権限エラーや通信エラーなど、状態を確認できない場合は停止します。
初回であってもサーバーが不在を明確に返さない場合は、原因を確認したうえで
手動実行の `Transfer all files` を有効にして初期化してください。
状態ファイル `test/fc2-deploy-state.json` はFC2の公開領域に保存され、パスとハッシュが
公開されます。FTPソフトなどで手動変更・削除したファイルは自動検出できないため、
その場合や状態に不安がある場合は `Transfer all files` を有効にして復旧してください。
転送元から削除された古いファイルは自動削除されません。
フィギュアなどのコレクションは、明示的な順序指定や日付順がない場合、
コンテンツID順で表示します。ビルド間で取得順が変わってもHTMLが変わりにくくなり、
差分転送を抑えられます。順序を導入した最初のデプロイでは、変更されたページが
まとまって転送される場合があります。
FC2へのデプロイは同時に1実行だけです。実行中に新しい自動・手動実行が複数追加されると、
待機中の古い実行は新しい実行に置き換わります。実行中の転送は中断されません。

FTP接続を調査する場合は、ワークフロー実行時に `Test FTP data connections
without building or uploading` を有効にすると、ビルドやアップロードを行わずに
`test` ディレクトリの一覧取得を確認できます。

FTPは通信を暗号化しないため、FTPパスワードやデータが通信経路上で漏えいする
リスクがあります。Secretsは保存時の保護であり、FTP転送を暗号化しません。
GitHubリポジトリやワークフローの編集権限も適切に制限してください。
FC2のFTP接続ロックは更新しない間は有効にしておくことを推奨します。

FC2有料版はディスク容量が合計10 GB、FTP経由の1ファイルの上限が1 GBです。
ワークフローはビルド後にサイズを表示し、1 GB超のファイルがあれば停止します。
FC2の残り容量は既存サイトと共有するため、公開前に管理画面でも確認してください。
転送元から削除された古いファイルはサーバーに残るため、必要に応じてFTPソフトで
整理してください。本番サイトのルートを転送先に指定しないでください。
